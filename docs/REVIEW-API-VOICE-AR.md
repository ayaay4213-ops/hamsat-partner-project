# مراجعة طبقة API والصوت — HAMSAT

تاريخ المراجعة: 2026-11-25  
الفرع: `review/hamsat-safe-transfer-plan-2026-11-25`  
نقطة الأساس: `197c6490b998ec0a138d068075c6db97b0ed682f`

## حدود المراجعة
- مراجعة قراءة فقط لملفات `js/api.js`, `js/supabase-auth.js`, `js/voice-room.js`, `js/livekit-room.js` ودوال LiveKit Edge Functions.
- فحص سياسات RLS وصلاحيات الأعمدة وبعض تعريفات الدوال في Supabase بعمليات SELECT فقط.
- لم تُعدّل ملفات التطبيق أو قاعدة البيانات أو إعدادات Auth/LiveKit.
- لم تُشغّل اختبارات قبول فعلية أو اتصالاً صوتياً من جهاز مستخدم.

## نتائج إيجابية مؤكدة
1. `js/api.js` يستخدم قائمة أعمدة صريحة لملفات المستخدمين العامة، ولا يطلب بيانات الهاتف أو البريد.
2. جدول `profiles` لا يحتوي على عمود هاتف؛ حقول الحظر الحساسة غير قابلة للقراءة عبر صلاحيات أعمدة authenticated التي فُحصت.
3. سياسات قاعدة البيانات تقصر قراءة المحافظ ومعاملاتها على صاحب المحفظة أو الإدارة.
4. سياسات الإشعارات تقصر القراءة والتحديث على `recipient_id = auth.uid()`.
5. سياسات الرسائل الخاصة تقصر القراءة والإرسال على طرفي المحادثة، مع مراعاة حظر المستخدم.
6. تحديثات طلبات الصداقة محصورة بالمستلم، وإجراءات كتم المشاركين في الغرفة محصورة بمالك الغرفة.
7. حماية حقول الدور والحظر ومستويات VIP/الثروة/الكاريزما موجودة عبر triggers؛ تغيير الدور الذاتي مرفوض، و`is_admin()` يتحقق من معرّف المالك الثابت مع دور الإدارة.
8. دوال الهدايا التي فُحصت تتحقق من المستخدم المسجل، وتتحقق من الرصيد والكمية، وتستخدم آلية منع تكرار الطلبات.
9. `agent_recharge_user` يتحقق من عضوية الوكالة النشطة وطريقة الدفع والمرجع، ويوجد فهرس فريد يمنع تكرار مرجع الدفع داخل الوكالة.
10. دالة `livekit-token` تتحقق من JWT وعضوية الغرفة وحالة الحظر ومقعد المايك قبل إصدار رمز محدود الصلاحيات؛ دوال الكتم والطرد تتحقق من أن المنفذ هو مالك الغرفة.

## نقاط متابعة قبل اعتماد الأمان
1. أظهر فحص Supabase Security Advisor عدد 53 دالة `SECURITY DEFINER` قابلة للتنفيذ من authenticated. هذا التحذير لا يثبت وحده وجود ثغرة، لأن بعض الدوال العامة مقصودة، لكن يجب مراجعة كل دالة على حدة والتأكد من فحص `auth.uid()` أو صلاحية الإدارة/المضيف داخلها، ومن عدم وجود مسارات غير محمية.
2. أظهر الفحص أن حماية كلمات المرور المسربة (HaveIBeenPwned) معطلة في إعدادات Supabase Auth. لم يتم تغيير هذا الإعداد.
3. جدولَا `private.gift_request_results` و`private.room_game_answer_keys` عليهما RLS دون سياسات؛ هذا قد يكون مقصوداً لأنهما ضمن schema خاصة، ويجب التأكد من أن الوصول يتم فقط عبر دوال الخادم المطلوبة.
4. يجب إجراء اختبارات وظيفية فعلية للهدايا والمحافظ والوكالات والمقاعد والرسائل والصوت قبل اعتبارها مكتملة.
5. لم يتم اختبار اتصال LiveKit من أجهزة وشبكات مختلفة؛ قراءة الشيفرة لا تثبت أن أسرار LiveKit وعنوانه متطابقة أو أن الاتصال يعمل ميدانياً.

## القرار
- لا يوجد نقل برمجي مقترح من الفروع القديمة في هذه المرحلة.
- لا تُغيّر قاعدة البيانات أو إعدادات Auth أو LiveKit بناءً على هذا التقرير وحده.
- تُستكمل مراجعة دوال `SECURITY DEFINER` واختبارات القبول قبل أي دمج أو نشر.
