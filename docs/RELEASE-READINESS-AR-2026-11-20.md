# جاهزية الإصدار الشامل — فحص قاعدة البيانات الحية
تاريخ الفحص: 2026-11-20

> هذه وثيقة تدقيق قراءة فقط. لم يتم تنفيذ SQL أو تطبيق migrations أو تعديل بيانات المستخدمين. لا تعني أسماء الجداول أن تدفقات التطبيق مكتملة؛ يلزم اختبار كل وظيفة من الواجهة وبحسابات منفصلة.

## ما تأكد وجوده في قاعدة البيانات الحالية
- الملفات الشخصية والغرف والأعضاء والمقاعد ورسائل الغرف.
- المحافظ والمعاملات والهدايا وسجل الهدايا ومقتنيات المتجر.
- الرسائل الخاصة والمحادثات والإشعارات وطلبات الصداقة والمتابعة.
- التقدم والمستويات والشارات ونقاط الخبرة.
- الألعاب وجلساتها وإجاباتها، وأحداث الغرف والقنبلة ومساهماتها ومكافآتها.
- الوكالات والأعضاء وإعادة الشحن ومحافظ الوكالات ودفاتر العمولات وسجلات التدقيق وجلسات المضيفين.
- الحظر والبلاغات وقيود المشاركين.
- كتالوج خلفيات الغرف وإطارات الملف الشخصي ضمن shop_items.

## فجوات بنيوية يجب إكمالها قبل ادعاء اكتمال المنتج
1. العائلات/الأندية: لا يظهر جدول عائلات أو عضوية عائلات أو ترتيب عائلات في مخطط public الحالي.
2. صلاحيات الموظفين المحدودة: عمود profiles.role الحالي مقيد إلى user/admin؛ لا يظهر نظام صلاحيات مفصلة للموظفين مع سجل منح/سحب.
3. فصل العملات: wallets الحالية تعرض balance واحداً؛ لا يظهر فصل مستقل بين الرصيد المدفوع وBonus Coins في هذا المخطط.
4. السحب الدولي: لم يظهر جدول طلبات سحب أو سجل تحويلات محلية أو دورة موافقات للسحب.
5. حضور الغرف العام: room_members موجود، لكن لا يوجد حالياً API تجميعي آمن لعدد الموجودين في كل غرفة؛ لذلك لا تعرض الواجهة أرقام حضور مباشرة تخمينية.
6. مزود OTP: وجود وظائف طلب/تحقق الهاتف في التطبيق لا يثبت ربط مزود SMS حقيقي؛ يظل هذا معلقاً إلى أن تُضبط بيانات المزود ويُختبر إرسال واستلام رمز فعلي.

## حالة migrations
- قاعدة البيانات الحية أبلغت عن migrations حتى 0059_require_room_membership_for_game_host.
- ملفا 0060_one_room_per_member و0061_room_chat_history_since_join موجودان في فرع التطوير بحسب سجل الملفات السابق، لكنهما غير موجودين في سجل migrations الحي وقت هذا الفحص.
- لا تطبق أي migration تلقائياً. يجب مراجعة أثرها وفحص البيانات الحالية أولاً ثم اختبارها في بيئة غير إنتاجية.

## إجراءات الأمان قبل أي توسعة مالية أو إدارية
- لا توسّع صلاحيات RLS ولا تستخدم بيانات user_metadata لتحديد الصلاحيات.
- أي نظام موظفين يجب أن تكون صلاحياته في قاعدة البيانات، مع تحقق خادمي وسجل تدقيق، لا مجرد إخفاء أزرار.
- أي فصل للأرصدة أو سحب يجب أن يعتمد دفتر قيود غير قابل للتلاعب من العميل، ومفاتيح idempotency، وموافقة إدارية مسجلة.
- لا تُجرى عمليات مالية حقيقية في الاختبارات.

## نتيجة هذا الفحص
الفحص قراءة فقط. لم تتغير قاعدة البيانات الحية، ولم تتغير Production أو النسخة الاحتياطية. لا تزال معاينات Vercel متوقفة مؤقتاً حسب إجراء حماية حد النشر. يجب إعادة تفعيلها قبل إنشاء معاينة اختبار نهائية، ثم إيقاف/تثبيت التغييرات وفق بوابة النشر المتفق عليها.
