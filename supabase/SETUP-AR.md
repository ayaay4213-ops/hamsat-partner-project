# إعداد الحسابات الحقيقية في همسات

هذه المرحلة تضيف أساس تسجيل الدخول عبر Supabase، لكنها لا تصبح فعالة قبل إنشاء مشروع Supabase وإضافة إعداداته وتطبيق ترحيل قاعدة البيانات.

## 1) إنشاء المشروع
1. افتحي https://supabase.com/dashboard وأنشئي مشروعًا جديدًا.
2. اختاري كلمة مرور قوية لقاعدة البيانات واحتفظي بها في مكان آمن.
3. من Project Settings ثم API انسخي Project URL وPublishable key (أو anon key القديم).
4. لا تنسخي service_role أو Secret key إلى ملفات الواجهة أو GitHub أو المحادثة.

## 2) إعداد ملفات المشروع
1. انسخي `supabase/config.example.js` إلى `supabase/config.js`.
2. ضعي Project URL والمفتاح العام فقط في الملف الجديد.
3. لا ترفعي `config.js` إلى GitHub؛ أضيفيه إلى .gitignore.
4. من SQL Editor شغّلي محتوى `supabase/migrations/0001_identity.sql`.

## 3) إعداد تسجيل البريد
- Authentication ثم URL Configuration: أضيفي رابط همسات المنشور إلى Site URL وRedirect URLs.
- Authentication ثم Providers: فعّلي Email.
- اختاري هل تريدين تأكيد البريد قبل السماح بالدخول (موصى به).
- اضبطي SMTP موثوقًا قبل الإطلاق العام؛ إعداد البريد الافتراضي قد يكون محدودًا.

## 4) إعداد الهاتف
- فعّلي Phone provider.
- اربطي مزود SMS مدعومًا من Supabase وأدخلي بياناته داخل لوحة Supabase فقط.
- حددي دولة الجزائر ورمزها الدولي +213 في تجربة الأرقام.
- لا يمكن إرسال OTP حقيقي قبل إعداد مزود SMS والتحقق من رصيده/حدوده.

## 5) اختبار آمن
- أنشئي حساب اختبار ببريد تملكينه.
- اختبري تأكيد البريد، تسجيل الدخول، تسجيل الخروج، واستعادة كلمة المرور.
- اختبري OTP على رقم تملكينه فقط.
- لا تستخدمي بيانات حقيقية للزوار قبل إكمال اختبار صلاحيات API وربط ملف المستخدم بالخادم.

## ما لا تزال هذه المرحلة لا تنفذه
- لا تستبدل بعدُ مصادقة Puter في كل واجهات API الحالية؛ يجب نقل API إلى التحقق من JWT الخاص بـ Supabase قبل اعتماد الجلسات الجديدة.
- لا تنفذ الغرف الصوتية أو الرسائل أو الهدايا أو لوحة الإدارة.
- لا تضعي مفاتيح الخدمة السرية في المتصفح.
